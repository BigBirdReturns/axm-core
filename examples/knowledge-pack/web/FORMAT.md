# Experimental transport: axm-pack-preview/0.1

The transport is a ZIP of regular files. `pack.json` indexes a format identifier, a head shard identity, and the included shard identities. Each canonical shard lives under `shards/<derived sh1_ identity>/`. The index is untrusted and does not add authority to the signed records. A reader checks actual inventory, verifies every shard with a separately supplied 1344-byte hybrid public key, derives identities from manifest bytes, requires complete included predecessor lineage, rejects cycles or disconnected history, and derives one unique head. An index claiming another head is rejected.

Limits: 8 MiB archive; 32 MiB expanded; 8 MiB per member; 1024 members; 32 shards; maximum expansion ratio 200. Reject encrypted entries, duplicate or case-colliding names, links, non-regular entries, unsafe relative paths, traversal, platform-reserved names, trailing-dot aliases, file/directory collisions, and duplicate JSON keys. Parsing a ZIP is never execution of its contents. Files are extracted only into a newly created temporary workspace, under bounded intake, and verified before becoming a displayed record.

Genesis owns signatures, Merkle roots, canonical tables, evidence binding, and shard identity. The transport leaves these unchanged. `content/original.txt` preserves the raw input bytes; the canonical normalized source carries the evidence spans. An archive SHA-256 identifies the transport bytes and is displayed separately from the Genesis-derived identity. ZIP compression and entry order are transport details.

The preview uses one explicit trusted publisher key per opened package. Multi-publisher trust, revocation discovery, external predecessor retrieval, richer packaging interoperability, and automatic semantic admission are not implemented by this preview. The creator emits successive signed records without modifying predecessor bytes; the reader demonstrates historical continuity, not automatic semantic merging.
